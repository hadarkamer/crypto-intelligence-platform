# Historical formula leaderboards before Stage 8 maturity

This priority slice answers which formulas lead before the Stage-8 five-parent
minimum can be satisfied. It does not weaken, bypass, or reinterpret that
minimum. Historical and prospective results are separate products with a
shared display vocabulary, not interchangeable evidence.

## Two explicitly separate reads

### Ordered-V7 Watch comparator

The immediately available source is the active all-Watch formula population.
Its coin-level and selected-timeframe views already freeze feature decisions,
select MATCH and control arms before reading outcomes, group observations by
`btc_parent_movement_id`, and expose Ordered First Touch V7 labels plus full
window MFE/MAE. The leaderboard reads those views only; it does not add a
migration, worker, source request, write, notification, or delivery path.

This source is named `WATCH_DESCRIPTIVE_ALL_CAPTURE_PHASES`. It intentionally
combines the Watch intake's historical and forward capture phases because the
existing aggregate views do not carry `capture_phase` through selection. It is
therefore a descriptive comparator, not a reconstructed historical Stage-8
cohort and never prospective evidence.

Every request fixes the population dimension, symbol scope, measurement
window, analysis direction, threshold, and—for selected-timeframe formulas—the
exact source timeframe. Rankings never pool these axes. Catalog definitions
with no closed outcomes remain counted, with a bounded sample of their keys;
they cannot receive a metric rank. Evidence bands distinguish no usable
evidence, one-to-four parents, and five-or-more descriptive parents.

Probability and asymmetry have separate rankings. There is no opaque combined
score. Probability ordering uses the documented Ordered-V7 reference-floor
checks, Wilson 95% lower bound, hit rate, and route parent count. Asymmetry
ordering uses the same policy's reference floors, route parent count,
sum-MFE/sum-MAE, favorable
dominance, and median paired edge. True metric ties share a dense rank; formula
identity is used only for deterministic display order. Control-arm rates and
lift remain diagnostics. The floors form a descriptive ordering tier only and
do not create Ordered-V7 acceptance or Stage-8 authority.

### Exact Stage-8 historical discovery

This slice freezes the fail-closed 432-cell presentation contract. Its input
must include a complete per-binding status ledger, an explicit half-open
cohort, one read-only repeatable-read database snapshot, source high-water
marks, exact Stage-8 source versions, evaluator identity, and route-specific
included/excluded BTC-parent provenance. `EVALUATED` requires a matching
evaluation even for n=0; omitted, blocked, or not-yet-evaluated bindings are
unranked and can never be relabeled as no evidence.

The exact follow-up source must read the frozen Stage-8 raw graph in one
explicit, half-open time cohort and one read-only repeatable-read snapshot. It
will calculate 54 threshold-independent representative spines (nine scopes by
six candidate-direction definitions) once, then join the eight Ordered-V7
threshold cells to emit all 432 bindings.

The Watch `ALL` aggregate cannot be renamed `ALL_BINANCE7`: Watch `ALL`
contains HYPE, while Stage 8 freezes exactly seven Binance symbols before
representative selection. Watch HYPE outcomes use the Hyperliquid perpetual
route and cannot substitute for Stage-8 HYPE Spot instrument `@107`. Both
differences remain explicit source incompatibilities rather than being repaired
after aggregation.

Historical Stage-8 discovery will expose `NO_EVIDENCE` and
`PROVISIONAL_N_LT_5`, including route-specific parent IDs and exclusions, but
will always force `research_qualified`, LIVE, Telegram, deployment, and trade
authority to false. It must never call the durable acceptance path as though a
pre-freeze observation were prospective.

## Prospective continuation

After a real database-issued freeze, the same presentation contract can read
persisted Stage-8 evaluation receipts. A future additive migration may define
an explicit current frontier, but must not modify migration 056 or its hashed
implementation artifacts. The frontier must choose the newest selection for a
named cohort first and then the newest evaluation of that exact selection. If
the newest selection is not evaluated, the result is
`AWAITING_EVALUATION`; an attractive older evaluation is never substituted.

Only the prospective path may report the atomic research gate:

```text
at least 5 distinct eligible btc_parent_movement_id values in one passing route
AND (probability route OR asymmetry route)
```

Even a prospective passing result remains `EXPERIMENTAL_RESEARCH_ONLY` and has
no implicit LIVE, Telegram, or trading effect.
